Une fois le code source écrit ,puis lancer par le compilateur (clang++ -c c1-exo7_main.cpp) on peut constater que le fichier objet obtenu est (c1-exo7_main.o).par la suite apres avoir lancer (.\c1-exo7_main.o) la ligne qui suit n'affiche pas (bonjour) mais revient plutot encore à la ligne de commande actulle (PS C:....) mais par ailleur apres avoir lancer (.\c1-exo7_main.o) une interface s'ouvres directement et nous demande de choisir d'ouvrir le fichier ailleur .
On constate aussi que dans l'editeur qu'il apparait aussi un autre fichier (~$-exo7_main.o) cela signifie que le fichier est temporairement verrouillé et quelle peut s'ouvrir comme un document sur Word et non comme un progrmme.on observe tout ces changements parceque la ligne de compilation (clang++ -c c1-exo7_main.cpp) avec le -c nous permet de cree un fichier objet mais spécifique sans le -o il cree donc de celui ci un fichier par de défaut (c1-exo7_main.o).ainsi lorsqu'on lance (.\c1-exo7_main.o) dans le terminal rien ne s'affiche tout simplent parceque ce fichier n'est pas reconnu comme 'executable'.
conclusion le -o est essentiel car il permet de nommer explicitement l'executable final produit par le linker.sans lui ,-c produit seulement un fichier .o (fichier objet) qui n'est doc pes executable.il contient donc du code machine'incomplet'.
